🏠 메인으로
STEP 1

메인 페이지 기획, 목차부터 잡았다

진행 과정 — 가장 먼저 README.md에 실습 목차(개요·사전 준비·실습 내용·결과 정리)를 정리했고, 이 구조를 그대로 index.html의 골격으로 옮겨 만들었습니다. 이후 동덕여자대학교의 시그니처 핑크 톤을 색상 테마로 정해 전체 페이지에 일관되게 적용했습니다.

어려웠던 점 — 목차를 "빈 골격" 형태로 바꿔달라고 했을 때, 어떤 구조를 원하는 건지 서로 의도가 정확히 맞지 않아 한 번에 반영되지 않았습니다. 처음 요청을 구체적으로 표현하는 것이 AI와의 협업에서 생각보다 중요하다는 걸 느꼈습니다.

STEP 2

Git 충돌, 그리고 첫 번째 push 실패

진행 과정 — README.md를 커밋한 뒤 main 브랜치에 바로 push를 시도했는데, 원격 저장소(origin/main)에 로컬에는 없는 커밋(CLAUDE.md 수정)이 먼저 올라가 있어 push가 거부됐습니다. origin의 변경 내용을 fetch로 받아온 뒤, 서로 다른 파일을 건드린 것을 확인하고 merge로 안전하게 합친 후 다시 push해서 해결했습니다.

어려웠던 점 — "non-fast-forward" 에러를 처음 마주쳤을 때 당황스러웠습니다. 강제로 덮어쓰는 대신, 원격 변경 내용을 먼저 확인하고 충돌 여부를 점검한 뒤 병합하는 순서를 지켜야 안전하다는 걸 배웠습니다.

STEP 3

코드는 올렸는데, 사이트는 왜 없지?

진행 과정 — index.html과 blog.html을 만들어 GitHub에 push까지 마쳤는데, 실제 웹사이트 주소로 들어가면 아무것도 뜨지 않았습니다. 알고 보니 GitHub 저장소에 파일이 올라가 있는 것과, 그 파일이 실제 인터넷 주소로 열리는 "사이트"가 되는 것은 별개였습니다. 저장소 Settings → Pages에서 배포 브랜치를 main으로 지정하고 나서야 https://songdahee0905.github.io/vibe-week1/ 주소로 정상 접속할 수 있었습니다.

어려웠던 점 — "커밋하고 푸시했으니 사이트가 만들어졌겠지"라고 생각했던 게 착각이었습니다. 저장소(코드 저장 공간)와 배포(실제 서비스되는 웹페이지)는 다른 단계라는 걸 직접 헤매면서 이해하게 됐습니다.
